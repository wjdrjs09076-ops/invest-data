# SEC 품질 점수 추출 로직 수정 기록 (2026-10-14)

대상: `scripts/build_quality_snapshot.py` → `data/quality_snapshot.json`
(종합 점수의 품질 블록, 가중치 0.15. invest-portal Top-5 스크립트도 이 파일을 읽음)

## 1. 발견

운영 중인 `data/quality_snapshot.json`(2026-03-12 생성)에서 S&P 500 503개 중 57개의 영업이익률이 ±100%를 벗어났다.
영업이익은 매출에서 비용을 뺀 값이라 매출보다 클 수 없다. 예: CRM 363%, AMD 233%, ALGN 434%.
MSFT는 매출 $19.95B, 영업이익 $38.3B로 영업이익이 매출의 두 배였다.

## 2. 원인

| 원인 | 내용 | 예 |
|---|---|---|
| 기간 혼합 | 10-K와 10-Q 값을 섞은 뒤 종료일이 가장 최근인 값 하나를 고름. 손익 항목은 분기(3개월) 값, 자본·자산은 시점 값이 되어 ROE·GP/A의 기간이 맞지 않음. 10-K에 실린 4분기(90일) 값도 그대로 채택 | 10월 데이터 기준 AAPL 순이익 = 2026년 6월 분기 값 |
| 낡은 태그 | 후보 태그 중 '값이 하나라도 있는 첫 태그'를 채택. 2018년 이후 회사들이 매출 태그를 바꿨는데, 예전 태그(`Revenues`)에 남은 과거 값이 최신 태그보다 먼저 채택됨 | MSFT 매출 = 2010-12-31 분기 값, CRM 매출 = 2017년 값 |
| 확인 없는 단위·기준 | 태그 아래 모든 단위를 확인 없이 합침. 순이익(지배/비지배)과 자본의 연결 기준을 짝짓지 않음 | — |

## 3. 수정 규칙

1. 손익 항목은 10-K(20-F/40-F, 정정본 포함)의 연간 값만 사용. 기간 길이 350~380일만 연간으로 인정(52/53주 회계연도 포함).
   SEC 응답의 `fy`/`fp`는 '문서'의 회계기간이라 비교기 수치에도 같은 값이 붙으므로 쓰지 않는다.
2. 회사별 최신 회계연도 말(FYE)을 정하고 모든 항목을 그 날짜로 맞춘다. 그 날짜에 값이 없으면 과거 값으로 채우지 않는다.
3. USD 단위만 사용. 같은 기간 값이 여러 공시에 있으면 가장 늦게 제출된 값(정정 반영).
4. 순이익이 지배기업 귀속(`NetIncomeLoss`)이면 자본도 지배기업 귀속(`StockholdersEquity`)을 우선 사용.
5. 영업이익>매출, 매출총이익>매출, 자본≤0, FYE가 550일 넘게 지난 경우는 해당 비율을 결측(점수 0.5 중립)으로 두고 `flags`에 남긴다.
6. 후보 태그 목록과 점수 산식(0.4·ROE + 0.4·GP/A + 0.2·영업이익률 백분위)은 바꾸지 않았다. 로직 변경 효과만 분리하기 위해서다.

## 4. 결과

### 4-1. 같은 데이터에 이전/수정 로직 적용 (`summary.json`, `comparison.csv`)

2026-10-14에 받은 SEC Company Facts 캐시 하나에 두 로직을 각각 적용. 비교 대상 497개(SEC 티커 매핑에 없는 6개 제외: AVB, BK, CTRA, EA, EQR, HOLX).

| 항목 | 이전 로직 | 수정 로직 |
|---|---|---|
| 영업이익 > 매출 | 24개 | 0개 |
| 매출총이익 > 매출 | 33개 | 0개 |
| 손익 항목 중 하나 이상이 10-Q 값 | 473개 | 0개 |
| 18개월 넘게 지난 값 포함 | 241개 | 1개 (PSKY: 최신 연간 FYE가 2024-12라 비율 계산에서 제외) |
| 비율의 분자·분모 기간 불일치 | 246개 | 0개 |
| 값이 있는 종목 (ROE / GP/A / 영업이익률) | 497 / 255 / 408 | 464 / 184 / 362 |

영업이익률이 −100% 아래인 MRNA(영업손실 > 매출)는 실제로 가능한 값이라 그대로 둔다.
값이 있는 종목 수가 줄어든 것은, 이전에 과거·분기 값으로 채워져 있던 칸이 비게 된 결과다.

### 4-2. 독립 출처 대조: Sharadar SF1 (`crosscheck_sf1_summary.json`)

`data/fundamentals.json`(Sharadar SF1 최신 연간, 2026-06-04 생성)과 회계기간 말이 같은 451개 종목만 비교. 상대 차이 0.5% 이내를 일치로 본다.

| 항목 | 이전 로직 일치 | 수정 로직 일치 |
|---|---|---|
| 매출 | 10 / 440 (2.3%) | 402 / 423 (95.0%) |
| 영업이익 | 0 / 377 (0%) | 295 / 347 (85.0%) |

참고로 지금 운영 중인 3월 파일을 12월 결산 종목 기준으로 SF1과 비교하면 매출 218/366(59.6%), 영업이익 227/305(74.4%)가 일치한다.

남은 불일치(매출 21건, 영업이익 52건)는 아직 원인을 확인하지 않았다. 매출 불일치 21건 중 11건이 금융업이라 업종별 매출 정의 차이가 후보이고, 영업이익은 SF1의 표준화 방식과 회사 보고값(`OperatingIncomeLoss`)의 차이가 후보다. 확인 전까지는 추출 오류로도, 정의 차이로도 단정하지 않는다.

## 5. 운영 반영 시 영향 (`topn_impact.json`)

invest-portal의 `build_strategy_topn_ci.py`를 같은 가격 데이터(2026-10-13까지)로 세 번 실행.

| 품질 입력 | 1/2 이후 누적 | 최대낙폭 | 현재 보유 |
|---|---|---|---|
| 운영 파일(2026-03) | +65.2% | −21.1% | IQV, MPC, MRK, PSX, TGT (사이트 파일과 동일) |
| 수정 파일 | +75.1% | −28.2% | FTNT, IQV, MPC, MRK, PSX |
| 품질 블록 없음 | +22.5% | −33.7% | CRL, IQV, MPC, PSX, VLO |

- 이 노셔널 기록은 매일 1/2부터 다시 시뮬레이션하면서 과거 구간에도 '현재' 품질 파일을 쓴다. 품질 파일만 바꿔도 누적 수익률이 크게 달라지므로, 이 수치를 규칙 고정 후 쌓인 기록으로 보기는 어렵다.
- 수정 파일로 바꾸면 사전등록 Top-5 페이퍼 계좌의 목표 종목 1개(TGT → FTNT)가 다음 리밸런싱에서 바뀐다. `FORWARD_TEST_TOP5.md`의 무수정 서약에 해당하므로, 반영 전에 기록 방식과 OOS 기점 리셋 여부를 정해야 한다.

## 6. 남은 한계

- 연간 값만 쓰므로 최신 분기가 반영되지 않는다. 9월 결산인 AAPL은 현재 FY2025(2025-09-27) 값을 쓴다. 최근 4개 분기 합(TTM)은 다음 단계 후보다.
- 후보 태그 목록을 넓히지 않아 일부가 결측이다. 예: DUK 매출(`RegulatedAndUnregulatedOperatingRevenue`), BKNG 순이익(`NetIncomeLossAvailableToCommonStockholdersBasic`).
- XOM은 SEC 티커 매핑이 새 지주회사(ExxonMobil Holdings Corp, CIK 2115436)로 바뀌어 연간 재무가 없다(중립 처리).
- CLX는 FY2026 10-K가 API에 아직 없어 FY2025 값을 쓴다.
- 같은 FYE에 매출 태그가 둘 이상이고 1% 넘게 다른 종목 41개(`revenue_tag_conflict`). 37개는 `Revenues`가 더 크고(총매출), 4개(ARES, NTAP, PPL, WMB)는 반대라 원문 확인이 필요하다.
- 스냅샷은 실행일 기준 최신 공시를 쓰므로 과거 백테스트용 시점(PIT) 데이터가 아니다.
